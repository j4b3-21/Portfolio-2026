## Problem

Placement season runs on spreadsheets, chat groups and hope. The placement cell imports students by hand, eligibility rules live in someone's head, recruiters can't see their own applicant pools, and students hear about drives late. Every college rebuilds this mess every year.

## Motivation

CampusHire is built for the Training & Placement cell of IIIT Tiruchirappalli — it encodes the process the cell runs by hand today: Excel imports, eligibility, drives, applications, offers and reporting.

## Technical decisions

- **Modular monolith on Spring Modulith** — module boundaries are verified in tests, not conventions.
- **Metadata-driven records**: modules and 17 field types are data; records are JSONB with canonical values, optimistic concurrency, history, soft delete and uniqueness. CampusHire's 11 modules install into an institute as a declarative *app pack*.
- **Three-layer authorization**: OpenFGA relationship checks per module, SQL record scopes on every read/write/export, and field-level security.
- **PostgreSQL 18 doing real work**: JSONB, GIN indexes, materialized views.
- **244 automated tests** (JUnit 5 + Testcontainers covering PostgreSQL, OpenFGA, Redis, Mailpit and MinIO) gate CI.
- **Production topology as code**: Docker Compose with Nginx (TLS), two stateless API replicas, Keycloak, PostgreSQL, OpenFGA, Redis, MinIO, plus Prometheus/Grafana and k6.

## Engineering challenges

Modeling eligibility as data instead of code, keeping Excel imports idempotent (dry run + downloadable error report), making OpenFGA tuple sync survive partial failure, and keeping a two-replica topology realistic about what it can serve.

## Lessons learned

Metadata-driven design is expensive for the first feature and cheap for every one after. Authorization is never "a middleware" — it's a data model.
