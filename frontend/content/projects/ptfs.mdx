## Problem

You don't understand a filesystem by using one. You understand it by *writing* one — by meeting the block layer, inodes and path resolution face to face, on an operating system small enough to hold in your head.

## Motivation

MIT's xv6 is the direct way in: a real, running Unix-like kernel with nothing hidden. The project modifies its filesystem in a way that is genuinely its own, not a tutorial's.

## Technical decisions

- Built **on xv6 rather than a toy simulation** — a real boot, a real disk image, a real constraint: if it corrupts the superblock, nothing boots.
- Priority tags as **first-class file metadata**, so retrieval can respect importance rather than only directory position.

## Engineering challenges

Reading a C kernel codebase with no safety net; understanding the on-disk layout well enough to extend it without breaking the boot path; debugging with print statements in a world without a debugger worth the name.
