## Problem

A technical fest is a firehose of events, schedules, venues and people — usually managed through a tangle of Google Forms and a pinned message. Participants can't see what's happening; organizers can't manage what they can't see.

## Motivation

Atrang is the institute's technical fest, and it deserved infrastructure as interesting as the events themselves — the fest treated as a *world*, not a form list. Built as the extended full-stack DBMS architecture project for the Database Management Systems Laboratory (24CS305 / CS3106).

## Technical decisions

- **A 3D world as navigation** — the fest rendered as an explorable space (Three.js / React Three Fiber); the public showcase lives at `/events`.
- **Session-cookie authentication**: same-site HttpOnly session cookie (`ATRANG_SESSION_ID`), passwords stored as BCrypt hashes (cost 10) — never plaintext.
- **Flyway migrations V1–V9**: five 3NF relational tables with NOT NULL / UNIQUE / CHECK constraints, foreign keys with explicit delete rules.
- **Database doing real work**: analytical views (`v_event_details`, `v_category_metrics`), an automated audit trigger (`trg_events_audit_log`), and a stored function (`fn_get_fest_stats()`) for system-wide metrics in one query.
